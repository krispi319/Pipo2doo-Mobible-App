# v1.4.4 / 155 — recurring task editing and deletion

## Behavior

The compact UI uses This task / From here / All open for edits and
This task / From here / Series for deletion. Full descriptions remain available
to screen readers; longer edit guidance is behind the info button. Selection,
counts, confirmation, retry and completed-history behavior are unchanged.

The 2026-11-01 approved visual refinement puts the recurring task title first,
adds a selected-pill checkmark, uses a compact time chip and tag action, and
allows private-note expansion (existing notes start open). All reminder options
remain available when enabled, and tag management remains in the tag picker.
Delete uses a red filled button. Create task and other pages keep their layouts.
Current native renders: v144/approved-editor.png and v144/approved-delete.png.

Existing daily copies are separate dated task records. The old editor defaulted
to one occurrence; its Future scope excluded earlier unfinished dates, and a
linked occurrence set to Once did not show series controls. Deletion only removed
one record. Existing daily links were inspected read-only and were intact.

Editing now offers:

| Choice | Effect |
| --- | --- |
| Only this occurrence | One dated task; other occurrences retain their details. |
| This and future occurrences | Changed title, assignee, list and tags on unfinished linked tasks from the selected date onward, plus later generation. |
| All unfinished occurrences | Those shared fields on all unfinished linked tasks, including earlier overdue and already planned tasks, plus later generation. |

Dates, times, repeat settings, private notes and personal reminders use Only this
occurrence. Completed titles/content, completion status/date and private details
are not rewritten by series edits. Changing a shared field does not reset other
customized shared fields. Future template selection preserves its schedule rather
than adopting a customized occurrence's time. Stopped history does not restart
daily generation when edited.

If one occurrence already has the corrected title, select All unfinished and Save
without changing other shared fields to synchronize that current title to the other
unfinished copies. Partner changes to fields untouched in the editor are preserved
by merging the series edit's intent into the latest selected task.

Delete task offers:

| Choice | Effect |
| --- | --- |
| Only this occurrence | Removes the selected task; future repeats continue. |
| This and future occurrences | Removes unfinished linked tasks from that date onward and stops later repeats. Earlier unfinished tasks and completed history stay. |
| Entire series | Removes all unfinished linked copies, including overdue and planned, and stops later repeats. Completed history stays. |

The dialog shows the reviewed unfinished count and waits for success. Cancellation
does nothing; failure retains the scope and supports retry. If no unfinished tasks
remain but the series is active, Stop repeats can retain all completed history.
Stopping a generator may change its repeat/link metadata; completed task content,
dates, status and private notes stay intact.

Series membership follows saved seriesId/parentId links, never matching titles.
An unrelated task also named Fix pipo2doo is unaffected. Manually recreated tasks
without saved recurrence links are not automatically merged by their names.

## Synchronization

The new invoker wrapper checks membership and the full active linked task ID set
under the same transaction lock used by generation. Existing record RPCs still
enforce versions and permissions. If another phone or the generator changes the
series after the reviewed snapshot, save/delete fails atomically and asks for a
refresh. Both partners retain editing rights; notification assignment rules remain.

The existing batch limit is 500 changed/deleted records. Larger operations fail
without partial writes. The new RPC adds no table, policy or task-data backfill.
Old installed apps remain compatible; the new controls require the v1.4.4 app.

## Two-phone acceptance (not performed by automated tests)

1. Open an existing daily occurrence, choose All unfinished occurrences, rename it,
   and save. Verify earlier unfinished and planned tasks on both phones. Completed
   history and an unrelated same-title task must stay unchanged.
2. Reopen the app and inspect newly generated days; confirm the corrected name.
3. Delete one date; confirm the rest of the series continues without duplicate days.
4. Delete Entire series after checking its count. Confirm unfinished tasks disappear
   on both phones, completed history remains, reminders clear after sync, and no
   new occurrences appear. Test network failure/retry and changes from the partner.
